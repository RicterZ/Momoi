# MCP 配置保存与重启

Dashboard 模式复用现有 `RuntimeSupervisor`：保存 MCP 配置后重启业务运行实例，
重新连接全部 MCP 服务并发现工具。Dashboard 和容器不重启；正在运行的对话可能中断。
没有独立的 MCP 热重载器。

## 前端保存配置

所有请求使用现有 dashboard JWT 认证。

1. `GET /api/settings/mcp` 获取文件原始内容，同时保存响应头 `ETag`。
2. `PATCH /api/settings/mcp` 直接发送完整 MCP JSON 对象，可携带 `If-Match: <ETag>` 防止旧内容覆盖新配置。
3. 保存成功返回 **202**，响应体是与 `GET /api/settings/configuration` 一致的配置快照。
   保存其中的 `revision`，轮询 `GET /api/settings/runtime`。
4. `state == "running"` 且 `applied_revision == revision` 表示生效；`state == "error"`
   时展示 `error`。`runtime_active` 表示是否仍有业务实例运行，包括回退实例。
   尚未配置模型或 channel 时会保持 `setup`，MCP 随后在业务实例启动时连接。

请求体不包 `document`，也不是逐字段合并。例如：

```json
{
  "mcpServers": {
    "search": {
      "command": "uvx",
      "args": ["mcp-server-fetch"],
      "description": "Fetch public web pages.",
      "optional": false
    }
  }
}
```

发送 `{"mcpServers": {}}` 移除全部 MCP 服务。禁用单个服务使用 `disabled: true`。
保存保留禁用项、扩展字段和环境变量引用，不展开或脱敏凭据。

| 状态码 | 含义 |
| --- | --- |
| 202 | 文件已保存，业务重启已请求；连接结果通过 runtime 状态获取 |
| 400 | JSON 或配置结构错误，或文件写入失败；不会请求应用无效配置 |
| 401 | 未通过 dashboard 认证 |
| 409 | `If-Match` 版本已过期，需重新读取配置 |

GET 仍原样返回文件，不要求现有文件合法，便于修复。缺失默认文件时返回空配置，缺失自定义路径时返回 404。
PATCH 写入 `tools.mcp_config` 指定的路径。旧工作区将该字段设为 `null` 或空字符串时，
通过此接口保存会将其设为 `mcp.json`，启用刚保存的配置。

新工作区默认创建空 `mcp.json` 并监听它，不覆盖已有文件。旧工作区的显式禁用设置保持不变；
若只手动编辑文件，需先将 `tools.mcp_config` 指向该文件。

## 重启后工具如何变化

| 变化 | 行为 |
| --- | --- |
| 未修改的服务 | 同样关闭旧连接并重新连接 |
| 服务参数、工具参数或 schema 修改 | 使用新连接重新发现的定义 |
| 删除、禁用服务或调整 `enabled_tools` | 新目录不再暴露被移除的工具 |
| 新增服务 | 连接成功后加入工具组目录，供模型按需启用 |
| 空工具目录 | 不提供 `tool_enable`；心跳的 `tool_groups` 只允许空数组 |

`tool_enable` 的组名、描述及 enum 从实际发现的工具生成；未连接成功的服务不会生成可用工具组。
MCP 服务原始名字与协议工具名字通过注册表映射，特殊字符规范化不会丢失分组描述。
运行实例重建后，当前对话的工具启用状态不保留；新对话按需重新启用。

## 失败与恢复

- **API 提交格式错误**：保存前拒绝，旧文件和运行实例保持原状。
- **手动编辑成错误格式、文件缺失或不可读**：检测到新版本后校验失败，保留原运行实例，状态报告错误。
- **必需 MCP 连接或工具发现失败**：新实例启动失败，清理其连接，尝试用上一份已验证的完整配置恢复。
  MCP 使用内存中的旧快照，避免再次读取已经改坏的文件。首次启动无旧配置时，只保留 dashboard 供修复。
- **可选 MCP 失败**：`optional: true` 允许其他服务和业务正常启动，失败服务不挂载工具，并记录连接失败。
- **调用不存在的工具或服务返回工具错误**：返回结构化失败；不会因单次工具错误重启业务实例。
  现有传输故障恢复会重建该会话，但不自动重放可能产生副作用的调用。
- **重启时未完成的调用**：旧实例先按现有停机流程退出；MCP 关闭时尚未完成的请求返回
  `mcp_stopped`。已经发出的请求标记 `ambiguous: true`，排队未发出的请求为 `false`，不自动重放。

回退恢复运行状态，不覆盖磁盘上被拒绝的配置，方便继续编辑。修正文件会被自动检测；
如果只是安装了缺失命令或修复网络，使用 `POST /api/settings/apply` 重试，返回 202。
配置文件检测沿用现有约 1 秒轮询，完成时间还取决于停机和 MCP 连接耗时。
纯后台模式仍需手动重启进程才能加载新配置。
