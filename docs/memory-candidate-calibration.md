# 写入候选数量：线上快照回放（2026-10-09）

结论：保留 `PER_REQUEST=8`。在当前样本上，把有效记忆候选从 8 扩到 12、16、24、32 没有找回更多历史操作目标；保留真实前台上下文时，现行混合检索在 8 已覆盖全部历史目标，扩大候选主要增加输入和预算压力。不能把这个结论理解为所有未来请求都能召回。

另一个独立修正：事实纠正使用 write/replace，保存用户有证据支持的新结论并淘汰旧版本；否定结论也是事实，不应转化成“不要记住旧事实”。forget 仅用于用户明确要求删除或不再保留。前台工具描述和后台提示词均已同步。没有清理线上历史 tombstone，也没有在这次实验中改变线上检索策略。

41 条改述是本次依据线上事实构造的诊断样本，不冒充线上真实请求。来源原话可能缺少当时的指代上下文，不把它们全部视为独立、完整的写入请求。

历史样本以系统当时实际修改/遗忘的 ID 作为目标，不宣称是人工穷尽标注的所有语义重复项。每个决定作为一个逻辑单元回放，同决定的多个请求一起查询；不将历史大批次的全部无关决定混在一起。按请求创建时间、版本创建时间、superseded_by 和遗忘时间近似重建当时的候选池，优先使用保存的上下文原文。将来创建的记录及当时已被替代的旧版本不会参加检索。

历史数据曾有原地编辑，且 tombstone 仅保存最终状态，无法完美还原每次历史读事务；这限制了统计的外推能力。当前 41 条记忆的诊断不需要重建历史。

## 实验设置

- 线上与本地模型一致：BAAI/bge-small-zh-v1.5，512 维，校准档 bge-small-zh-v1.5-momoi-v1，候选支持门槛 0.54。
- 本地真实编码文本并计算余弦相似度；使用实际 WriteCandidates 选取逻辑、相同查询前缀、文档模板、scope 过滤和向量预取宽度。不调用 LLM 来生成这部分命中指标。
- 对比每查询上限 4、8、12、16、24、32；累计预算仍为 32 条、正文估算 8000 tokens。
- `retrieval`：隐藏指定目标 ID 和前台可见上下文，测试首轮检索自身。完全同文优先保留规则仍适用。
- `host`：保留真实 target_id 和有效可见上下文，测试实际输入路径。
- `active_only`：仅有效版本，诊断有效记忆检索本身。**这不是当前生产默认行为。**
- `with_forgotten`：按当前代码把遗忘警戒记录放入检索池，与有效记录竞争候选额度。

token 数据是项目估算器对候选 XML 的估计，含候选自身字段及引用；不包含系统提示词、工具 schema 和另外加载的 owner_evidence，不能当成完整请求实际 token 账单。候选超出历史目标不等于无关噪声，本实验没有足够标注计算精确率。

K=8、隐藏上下文时，平均选中 8.4 条记录，其中 5.35 条是遗忘警戒。平均值超过 8，是因为一个决定可包含多条查询，以及指定/同文目标另行保留。

这说明旧遗忘记录确实在争占名额；不能靠无限扩 K 解决。也不能把上述“有上下文 58/58”宣传为向量检索召回率，它包含前台已提供的目标。

240 条 tombstone 中 157 条来自 dashboard 删除，83 条来自其他历史操作。证据里既有明确删除，也有旧架构下的事实更新、过时安排；不适合不加审查地视为永久禁止记忆。这次只做区分统计，没有批量恢复或删除它们。未来若调整遗忘警戒的保留方式或候选配额，应重新运行同样的比较。

## 当前有效记忆诊断

41 条完整同义改述，在所有 K 下均命中 41/41。只看有效候选，K=8 平均选中 2 条、候选 XML 约 332 tokens；12 以上没有变化。8 是上限，不是每次强行填满八条。

41 条未经上下文补全的来源原话，在所有 K 下均命中 31/41；十个未命中目标均未过 0.54。原话中的简短确认、指代和片段缺少完整检索意图，这类问题需要利用 transcript 补全查询或进行补查，单纯扩大 K 没有改善。

## 复现与数据保存

脚本：[calibrate_memory_candidates.py](../scripts/calibrate_memory_candidates.py)。输入是只读导出的 JSON，至少含 `memories`、`memory_tombstones`、`memory_operation_batches` 三个数组，字段与数据库同名。

本机复现本次完整实验：

```bash
uv run --locked python scripts/calibrate_memory_candidates.py \
  --snapshot /tmp/momoi-candidate-calibration/production.json \
  --extra-cases /tmp/momoi-candidate-calibration/extra-cases.json \
  --output /tmp/momoi-candidate-calibration
```

省略 `--extra-cases` 只测历史真实操作。输出的 `cases.json`、`measurements.json` 和 `vectors.json` 含用户数据，留在本机，不提交到仓库。已核验输出日志为 `/tmp/momoi-candidate-calibration/verified-measure.log`；纠正/遗忘模型回放结果在同目录 `correction-replay/`。

没有调低 0.54，没有增加全库 LLM 判重，没有清理线上遗忘记录，没有部署。本次选择是“在现有样本和现有累计预算下保留 8”，不是证明 8 在任何规模上都最优。
