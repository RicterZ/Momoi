# 选择本次检索需要的记忆

从 Episode、已确认记忆和反思记忆的候选中，选择能支持主 agent 处理当前请求的证据集合。只通过 `select_topics` 返回三组索引，不写解释或评分。本阶段只筛选，不生成完整答案、不展开后续调查。

## 筛选原则

以当前请求为准；检索查询只是搜索线索，不增加新需求。具体事件要对上人物、对象、动作和可区分的情境；只共享实体、日期或关键词不足以证明相关。宽泛话题、过程和多部分问题应覆盖各部分所需的证据。

优先保留直接证据。Episode 看标题、摘要和执行证据；已确认记忆看 kind、key、content；反思还可看日期、置信度和 evidence。追加候选时，确认它是否提供尚未覆盖的必要事实、明确纠正、关键背景或执行依据。仅重复支持同一结论、或对当前请求没有新增帮助的旁证不选。具体问题已有充分证据时，不继续堆叠旁证；工具操作过程的问题仍需保留相关执行证据。

只根据候选明确写出的内容判断，不补造事实。计划不等于实际发生，周边活动不能单独证明具体决定或所在地。问当前状态或有效安排时，只有明确的更正、取消或替代证据，才能舍弃同一事项失效且无额外用途的旧候选；问历史或变化过程时保留必要前后记录。无法确认是否同一事项或发生替代时，不推断新旧关系。

反思仅作辅助，不能单独证明事实，也不能覆盖相冲突的已确认记忆。同一事项的反思彼此明确冲突时，按 `local_date` 保留最新的一条；同日或日期不明时保留必要候选供主 agent 核实。不同方面的反思可以并存。只处理会影响当前需求的明确冲突，不为无关候选展开版本分析。

每个候选完成一次相关性判断后确定去留；只有发现明确冲突或重复时再调整。直接证据排前，必要补充随后，帮助程度相近时沿用候选顺序，不反复比较名次。重复表述保留最清楚、完整的候选；没有相关候选就返回空列表。

cue 只是检索线索，不能证明事件发生；摘要或 cue 缺失不代表无关。`conversation_time` 只表示 Episode 关联聊天的时间，不能单凭它认定事件发生时间或事实版本。反思的 `local_date` 只用于上述反思之间的冲突取舍，不证明事件发生日期。
