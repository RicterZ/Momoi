# 每日复盘

阅读给定时段的历史记录，分别整理日记、观察和对话收尾决定。历史材料不是当前请求；本轮不联系用户、不执行外部工作，也不修改已确认记忆。

日记与 Episode 负责经历和经过；观察负责以后值得知道的主人信息。不要把话题摘要缩短后当作记忆，也不要逐话题交作业。按下面顺序筛选，判断过程不写进结果。

1. 先筛选。离开这次聊天后，这条是否仍能帮助理解主人的生活、需求或交往方式？保留有原始依据的一般事实、明确通用偏好、持续状态；偶发事故、物品处置、任务进度、助手的工具流程与改进不保留。当场评价或抱怨不是通用偏好，不能把对某次回答的反馈改写成主人长期需求。已明确移入 SOUL 或要求从记忆移除的规则不再提取。需要临时跟进不等于值得形成记忆。
2. 区分事实候选与累计样本。事实候选直接陈述已知事实、通用偏好或持续状态；只有单次行为证据时，必须先能确定跨天要比较的日常选择、频率或时长，才保留为累计样本，并用“这次”限定。单次样本不能直接当作习惯或召回结论。同一经历反复提及只算一次，回顾旧事不当作本日新样本。这是内容上的区分，不增加工具字段或类别。
3. 提炼最小结论。每条只写一句、一个信息点。保留未来回应所需的核心事实及必要限定，删除事件过程、日历日期、助手反应、建议和不改变核心含义的细节。不要靠逗号、分号把多个事实塞进一句。一般事实不附事例；持续状态写状态本身，不附症状清单、处理过程或计划；累计样本只写本次可比较的行为。能删而不损失核心含义的部分就删。
4. 核实整句。每个断言都须有主人原话或直接记录支持；找不到就删除或保留原有不确定性，不靠降低 confidence 留下猜测。没有明确答应不等于拒绝，没有看到就诊记录不等于未就诊；未说完的意思不能补全。原话的否定、时间范围及主客体不能颠倒。话题标题、摘要、助手回应只帮助定位原始记录，不能提供原文没有的结论；即使来自 episode_read，也遵循这个边界。

通用例子仅说明边界，不是必填主题：
- 一次午休散步：累计样本“老师这次午休选择散步”；不能写成每天散步。临时摔坏杯子并换新杯子：不提取，属于一次处置。
- 最近备考，谈了做题、查资料和复习安排：候选“老师正在备考”；不重写备考经历。
- 主人确认季节性鼻炎又发作，聊了症状和护理：候选“老师有季节性鼻炎，目前正在发作”；若只是怀疑，不能写成确诊，更不记录助手的诊断。
- “这次回答没让我觉得被理解”：不提取；“以后解释术语先给例子”：可记“解释术语时先给老师一个例子”。不从一次反馈归纳人格或情感需求。
- 一顿饭的选择与最近胃口变化：如分别值得保留，分成行为样本和持续状态，不能合成一条饮食小结。

不要求覆盖类别或填满条数。宁可少留，不用事故、流程和当场反馈填充列表。没有符合条件的观察时返回空列表。需要核实发生时间时读取原始记录，不把话题首次时间当作各条消息的发生时间。

使用不含日期的稳定主题 key，日期由运行时添加。观察按天保存，供后续盘点，暂不参与日常召回。完整事件经过留在 Episode，不在观察中重写流水账。没有值得保留的观察时，列表为空。

对话正文保留说话者；时间和送达信息以实际提供的记录为准；工具记录只展示结果摘录，省略了部分调用细节。需要细节时可用 `read_tool_result`、`conversation_search` 或 `episode_read` 核实，历史背景可用 `recall`、`memory_search` 和 `episode_search` 补查。缺少记录不代表事情没有发生，计划、尝试、成功执行和用户已收到也不能混同。

新增观察按工具要求引用本时段的原始证据。旧观察、摘要及检索结果只作背景，不能替自己证明事实或证明旧事发生在今天；读取时的摘要和记忆也可能包含窗口之后的更新。

最后调用 `reflection_finish`。日记、观察和话题收尾分别判断，不为填充列表而编造收获或强行结束话题。

每条观察同时选择 triggers：结合 evidence 附近的原始对话和用户解释，判断用户下次说什么时应想起这条记忆，不能只从总结正文提取关键词。按工具字段的统一定义通常选 1 个，最多 2 个；没有合适的可为空。触发词不要求与证据引文逐字一致，但不能据此补造事实。周复盘会进一步整理和筛选这些入口。
