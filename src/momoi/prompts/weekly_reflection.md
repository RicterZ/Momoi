# 每周观察累计

阅读本周按天列出的主人观察，以及上次保留的候选。只整理关于主人的事实、习惯、偏好和互动要求；助手自己的经历、情绪、工具经验不进入候选。本轮不写入真实记忆、不联系用户。

每个候选只表达一个有依据的认识。content 通常为一句简短结论，保留主体、对象、适用情境和必要的不确定性；不写证据、引用编号、支持次数或取证日期。不要把阶段性状态改成永久属性。先找跨事件共同支持的最小结论，正文只留下未来回应需要知道的核心事实，不附事件举例、症状清单、处理过程、助手回应或就医安排；这些细节留在 events。不要用括号、逗号把多个结论塞进一句。每日观察也是待审材料，不照抄其中的扩写：引文未支持的推测不保留，尤其不能由未看到检查记录断言尚未检查。材料不支持时不要凑类别、扩大含义或拼接同主题的不同结论。

累计的是独立事件，不是提及次数。events 中每组 refs 表示同一次经历：引用本周 observation ID 或以前 event ID，并用 summary 简述该经历供下周识别。同一事件的继续、旧事回顾和多次提及合成一组；合并旧事件时必须引用旧 ID，不能把重提日期当新事件日期。已有候选尽量复用 key，完整保留仍支持该结论的旧事件；不得把旧事件拆成多个支持样本。缺失一天的记录不表示没有发生。

程序负责去重、最多一个月的有效期和计数：2～4 次为观察，5 次及以上为待准入；不足两次暂存供下周累计。次数不代表确定性，也不是凑足的目标。达到次数也不自动进入 recall，必须由用户在后台手动准入。明确事实一次出现可以保留为线索，但本轮不能绕过人工准入。

与结论冲突的观察 ID 放 conflicts，不计作支持。先区分不同情境与真实变化；解释不了的冲突保留，不用较新的日期直接否定旧事实。不能把之前的冲突重新标成支持。用户手动编辑后的候选正文以后台版本为准；不在本轮改变其含义。

related_memories 仅供检查重复和冲突，不是新发生的证据，不增加次数。若已有记忆已经完整覆盖某个新候选，不另建同义项；需要修改已有记忆的变化也只整理成候选，不能直接覆盖。

以下只说明边界，不指定要寻找的主题：
- 多次独立选座避开嘈杂处 → “老师选座时偏好安静的位置”，不扩大为“不喜欢社交”。
- 本周再次聊上周的一次游泳 → 与上周事件合并，不写“每周游泳”。
- 反复要求不要照抄发言 → “不要复述或者引用用户的发言，而是直接作出反应”，不附纠正经过。
- 多天延续同一项待办 → 同一状态的继续，不当作多次习惯证据。

调用 weekly_reflection_finish。summary 只简述材料覆盖和局限；findings 提交新增或有更新的候选，未改变的旧候选可省略。没有新增观察时不编造输出。事件引用只放结构字段，不能进入记忆正文。

每条候选同时输出 triggers，按工具字段中的统一触发词定义选择：通常 1 个，仅不同聊天入口需要时选第 2 个，优先用户原话，结合所提供的语境理解其用法，不凑数。触发词不计入证据；只有人工准入后才参与记忆触发。用户手动编辑过的候选保留已有触发词。
