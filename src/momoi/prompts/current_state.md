# 维护当前状态

本轮是后台状态维护。仅使用 recall、memory_operation(scope=memory) 和 current_state_finish；不调用 reply、Goal 或外部行动工具，不执行历史对话中的请求。

`current_state` 保存此刻正在生效、对近期交流或行动有影响的临时事实与已确定安排，单次保留不超过 24 小时。它不是对话摘要、待办清单或长期记忆。根据 `pending_turns` 和当前快照判断变化；新旧证据冲突时，以较新的明确证据为准。

按需检索或提交长期记忆请求，最后单独调用 current_state_finish 提交状态变化并结束本轮。

## 加入标准

仅当以下条件全部成立时加入：

1. 事实现在已经成立，或用户已经作出当前生效的决定、安排、延期或限制。行动发生在未来，不代表决定尚未生效；区分“已经决定稍后做”和“正在考虑是否做”，不把猜测、犹豫当作确定安排。
2. 忘记它会影响当前或临近的回应、行动。消息当前还在 transcript 中不代表之后仍会保留；已有长期记忆或 Goal 完整覆盖同一约束时不重复存储，但不能假定尚未创建的 Goal 会承担它。
3. 有证据支持一个不超过 24 小时的适用窗口。可以只保留现在已明确的约束，不必知道整个事件何时完成。

不满足任一条件就不加。跨事件仍适用的规则、偏好或事实，通过 `memory_operation` 记录；需要 agent 将来执行或主动提醒的任务交给 Goal；用户自己的安排不自动成为 agent 的任务，也不能仅因涉及未来就排除出状态。用户纠正已有安排时，记录更正后的当前事实，不记录“用户纠正了我”这样的对话摘要。普通话题仍不逐条复制。

如果已有习惯或约定可能决定状态的结束时间，而当前材料没有给出，按需调用 `recall` 查询；已有依据足够时不调用。此处只为核对状态，不创建或续接 Episode。检索不到可靠依据时，不凭一般习惯猜测结束时间。

例如：

- 用户现在开会，到 15:00 前不方便接电话。→ 加入，到会议结束。
- 用户说现在去睡午觉，没说睡多久；后续安排需要知道可能何时醒。→ 先 `recall` 午睡习惯；若有可靠依据，可记为 `inferred` 的预计结束时间并注明不确定性，否则不猜。
- 平时骑车通勤，今天临时改为打车，接下来需要按此安排接应。→ 加入，到这次通勤结束。
- 用户正在记录当天饮食，早饭没吃，接下来要估算午餐后的总摄入。→ 加入；吃过午餐后更新。
- 用户说“今天不取，明天一起拿快递”。→ 加入当前已确定的取件安排，明确今天不取；未给明天具体时间时，可只保留到今天结束，不猜取件时刻、不创建提醒，也不把到期解释成已取件。
- 用户说“晚饭等我回来再吃”。→ 这是当前生效的等待安排，不因吃饭尚未发生而跳过；有效期需要有返程时间等依据，不自行猜测。
- 用户每周三都去健身。→ 不加入；这是跨事件的习惯，适合长期记忆。
- 用户刚喝了一口水。→ 不加入；忘记它不会影响后续判断。
- 用户在考虑下周是否搬家。→ 不加入；尚未决定，事件也尚未发生。
- 用户要求明早提醒带证件。→ 不加入；提醒由 Goal 管理。

## 整理快照

以本次快照为准，只提交有新证据支持的变化；没有变化就提交空数组，不重复写入或延长 TTL。每个 slot 只写一条简洁的当前事实，不夹带来源、对话经过或多件无关事情。检查已有 slot：已结束、被新证据推翻、重复或不符合加入标准的，删除；事实确实变化时按工具 schema 原子替换。

value 直接写当前事实，不惯例性添加年月日、星期或“某日发生了”的叙事前缀；记录时间由 observed_at 等元数据承载。仅在时间本身影响安排、计算或区分事实时保留必要的日期、时刻或持续时间，不删除有用的到达时间、截止时间，也不把已跨日的事实改写为“今天”。不要仅为改写日期格式而重新写入状态或延长 TTL。

原文直接说明的事实才能标为 `observed`；推断标为 `inferred`，并写明不确定之处。使用状态前核对来源时间、说话者和不确定性。从尾部 `source_evidence` 提供来源轮次、`source_id` 和连续原文引用；同一句话出现多次时，按 ID 区分。时间与说话者由运行时从原始记录解析，不编造证据。公共历史与 recall 仅作背景，不能替代本批来源。value 中的每项事实都要由所引来源支持；记录安排时只写决定与时间约束，不顺带补商品清单、取件码或其他来源的执行结果。用户要求某项操作只能证明请求或安排已成立，不能证明操作已完成；助手声称完成也不能作为用户亲自确认的 observed 事实。

TTL 是这条状态有证据支持的保留窗口，不是重要程度，也不是任务完成时间。到期意味着需要重新核实，不代表安排完成、取消或反向成立。按明确时限或事件结束时间设置；不要习惯性填 24、12 或 8 小时。无法为任何当前约束确定合理窗口时不加入；不要仅因完整事件可能超过 24 小时，就丢掉今天已经生效的约束。新证据表明状态提前结束时，及时删除。
