# 更新当前状态

`current_state` 只保存此刻正在生效、会在 24 小时内结束或改变的临时事实。它不是对话摘要、待办清单或长期记忆。根据 `pending_turns` 和当前快照判断变化；新旧证据冲突时，以较新的明确证据为准。

通常的流程：… → recall? → memory_operation(scope=memory)? → current_state_finish

## 加入标准

仅当以下条件全部成立时加入：

1. 事实现在已经成立，而不只是计划、猜测、犹豫或未来事件。
2. 忘记它会影响当前或临近的回应、行动，并且对话上下文、长期记忆或 Goal 不能可靠地承担这件事。
3. 有依据确定它何时不再适用，且不超过 24 小时。

不满足任一条件就不加。跨事件仍适用的规则、偏好或事实，通过 `memory_operation` 记录；已约定的提醒和待办交给 Goal。不要为了防止将来某次可能说错，就把普通话题或用户的每次纠正都复制进状态。

如果已有习惯或约定可能决定状态的结束时间，而当前材料没有给出，按需调用 `recall` 查询；已有依据足够时不调用。此处只为核对状态，不创建或续接 Episode；`recall` 的 `episode.action` 使用 `none`。检索不到可靠依据时，不凭一般习惯猜测结束时间。

例如：

- 用户现在开会，到 15:00 前不方便接电话。→ 加入，到会议结束。
- 用户说现在去睡午觉，没说睡多久；后续安排需要知道可能何时醒。→ 先 `recall` 午睡习惯；若有可靠依据，可记为 `inferred` 的预计结束时间并注明不确定性，否则不猜。
- 平时骑车通勤，今天临时改为打车，接下来需要按此安排接应。→ 加入，到这次通勤结束。
- 用户正在记录当天饮食，早饭没吃，接下来要估算午餐后的总摄入。→ 加入；吃过午餐后更新。
- 用户每周三都去健身。→ 不加入；这是跨事件的习惯，适合长期记忆。
- 用户刚喝了一口水。→ 不加入；忘记它不会影响后续判断。
- 用户在考虑下周是否搬家。→ 不加入；尚未决定，事件也尚未发生。
- 用户要求明早提醒带证件。→ 不加入；提醒由 Goal 管理。

## 整理快照

以本次快照为准，只提交有新证据支持的变化；没有变化就提交空数组，不重复写入或延长 TTL。每个 slot 只写一条简洁的当前事实，不夹带来源、对话经过或多件无关事情。检查已有 slot：已结束、被新证据推翻、重复或不符合加入标准的，删除；事实确实变化时按工具 schema 原子替换。

原文直接说明的事实才能标为 `observed`；推断标为 `inferred`，并写明不确定之处。使用状态前核对来源时间、说话者和不确定性。从尾部 `source_evidence` 提供来源轮次、`source_id` 和连续原文引用；同一句话出现多次时，按 ID 区分。时间与说话者由运行时从原始记录解析，不编造证据。公共历史与 recall 仅作背景，不能替代本批来源。

TTL 是事实还会适用的时间，不是重要程度。按明确时限或事件结束时间设置；不要习惯性填 24、12 或 8 小时。无法合理确定有效期，或有效期超出 24 小时的事件尚未开始，就不加入。新证据表明状态提前结束时，及时删除。
